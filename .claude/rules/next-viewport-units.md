# ビューポート高さとモバイルのブラウザ UI

`vh` は「アドレスバー等のブラウザ UI が引っ込んだ状態」の高さで固定される。一方
`position: fixed` の要素はモバイルでは**実際の可視領域**に張り付く。この 2 つは一致
しないので、`fixed` なオーバーレイの高さを `vh` で取ると、ブラウザ UI の分だけはみ出す
（下寄せなら上が、上寄せなら下が見切れる）。

- 全画面オーバーレイ（モーダル / ボトムシート / ドロワー）の高さは `svh` を基準にするか、
  可視領域を基準にしたコンテナに対する `%` で取る。実例は
  `next/src/components/CharacterPickerDialog.tsx`（`fixed inset-0 h-svh` +
  パネル `h-[90%]`）
- `h-[calc(100vh-60px)]` のようなマジックナンバー補正はしない。ブラウザ UI の実寸は
  Safari / Chrome / 端末で違う。`svh` なら「UI が最大展開された時の可視高さ」を
  ブラウザ自身が計算するので、その差分を我々が知る必要がなくなる
- `dvh` はアドレスバーの出入りで高さが変動してガタつくため、シート類には `svh` を選ぶ
- ページ全体の最小高さのように、多少はみ出しても害のない箇所は `min-h-screen` のままでよい

**エミュレーションでは再現しない**: DevTools のデバイスモードや Playwright には
アドレスバーが存在せず `lvh == svh == dvh` になるため、このズレは原理的に発生しない。
「エミュで見て大丈夫だった」はこのクラスのバグの保証にならない。オーバーレイの高さを
触ったら、実機か iOS Simulator の Safari で確認する。
